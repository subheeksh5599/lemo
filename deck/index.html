The gap Architecture
The gap

Revive is live. The WASM contract module is only listed.

Portaldot V3 runs EVM contracts through Revive today. The WASM contracts module is listed for V3.0 but is not live or documented. Native assets, identity, vesting and proxy or multisig records already exist in the runtime.

When the module lands, the two will share validators and finality but not contract storage. A proof has to cross, because a call cannot.

Consequence Failure modes
The consequence

Without a proof that crosses, the two halves cannot see each other.

Four failures follow from one missing piece. If no runtime can prove the other's state, no ownership rule can cross the boundary.

01

Ownership stops at the boundary

Native ownership rules do not automatically follow an ERC-20 or ERC-721 representation.

02

EVM apps cannot read the conditions

Solidity sees a token. It cannot see the identity, vesting or permission rules that make it valid.

03

Unlocking can strand a representation

Backing can leave while tokens still circulate, unless the EVM state is checked first.

04

A sync service becomes the authority

The alternative to proofs is a privileged operator that every user has to trust.

Wrapping moves the asset. It does not enforce the relationship between the backing and its representation.

Rule one EVM transfer
Rule one

An EVM transfer needs a finalized, current native proof.

Before any ERC-20 or ERC-721 transfer settles, the EVM face proves that the native title still authorizes it.

The proof must establish
01

The title exists at the proven state root.

02

Backing is still bound to that title.

03

Native identity conditions are still satisfied.

04

Vesting still permits the movement.

05

The revision is current, and the proof head is finalized and fresh.

This is the design rule, not a deployed check. A valid signature over stale state is not a valid proof.

Allowtransfer settles

All five checks pass against one finalized native root, and the proven revision equals the revision the token last accepted.

Revertsupply untouched

Identity cleared, backing unbound, vesting expired, proof stale, or proof from revision r-1. The transfer does not settle.

The hard part Verification
The hard part

The work is proof plumbing, not the token contract.

Five problems decide whether this protocol is real. Each one is a requirement, not a later optimization.

ProblemWhat must holdThe failure it prevents
01 Finality Verify against a finalized state root, never against a head an RPC simply reports. A reorg erases the state that authorized a transfer after it settled.
02 Freshness A proof accepted once cannot authorize a second, later action. A title that changed is moved again on the strength of old bytes.
03 Revision binding Every proof names the revision it proves. Any property change increments it. Cleared identity or unbound backing leaves old proofs looking current.
04 Replay protection Bind proof to chain id, genesis, title, runtime, contract, operation and nonce. One proof is reused across titles, contracts or chains.
05 Interrupted transitions Order mint, burn and unlock so a failed step cannot strand or duplicate value. A burn without an unlock, or an unlock while supply still exists.
eth_getProof / -32601

The testnet EVM endpoint does not implement account proofs. The EVM witness path needs a real source before rule one can be enforced. We report the node's refusal rather than invent a witness.

Enforcement lives in the receiving runtime. A message is never the authority. Root source today is a trusted finalized checkpoint, and removing that trust is part of the work.

Why Portaldot One live, one listed
Why Portaldot

This model needs both runtimes. Portaldot has one live and one listed.

NetworkWhat it gives the assetWhat is missing
Portaldot today / Revive only ERC-20 and ERC-721 markets, Solidity applications, live finality, and native assets, identity, vesting and proxy records in the runtime. No WASM contracts module, so no on-chain native title for a verifier to read.
WASM contracts only, elsewhere Contract-level native ownership, identity, vesting and permission rules. No EVM market. The representation has nowhere to execute.
Portaldot with both Revive live now, WASM contracts module for V3.0, one finality. Proofs can cross once both exist. The native gate cannot be enforced until that module ships.

The asset does not choose between WASM and EVM. It belongs to both, and neither can act without proving that the other agrees.

LEMO design invariant / not yet enforced end to end
No cross-call dependency. ink! to Solidity calls are awaiting confirmation. The design moves proof bytes instead, and carrying them authorizes nothing.

The EVM-side gate is buildable now. The native-side check waits on the module. Statement Store stays a noticeboard: signed announcements, never authorization.

Shared finality

The proof and the state it proves settle under one validator set.

Two verifiers

One on EVM now, one native when the module ships.

No relayer authority

A relayer can carry bytes. It cannot make a bad proof verify.

Build the EVM gate now. Build the native gate when the module ships.

The design is public and the console is live. What is missing is the deployed pair: an EVM gate with a real title source, a native gate once the WASM contracts module lands, and the rejection cases proven on chain.

Confirm the WASM contracts module on V3 testnet, and Statement Store support on the target node.

M2 / TITLE AND GATE

Registry plus EVM verifier

Title registry with real backing. EVM verifier deployed against the same title id and revision.

M3 / BOTH DIRECTIONS

Two verifiers, two roots

Native state proven on EVM, EVM state proven on native, each against a finalized head.

M4 / REJECTIONS

Break it on purpose

Cleared identity, unbound backing, stale or replayed proof, outstanding supply. Then redeem and unlock.

What we need

Engineering time to land M2 to M4, a security review before any real asset uses this, and a Portaldot contact to confirm the WASM module and Statement Store timelines. No capital ask, no token sale, no fake traction.
